For developersडेवलपर के लिए

Everything on the portal comes from open web APIs that return JSON. There are three layers. The lower two follow two public documents; the top one is our research addition.

पोर्टल पर सब कुछ खुले वेब API से आता है जो JSON लौटाते हैं। तीन परतें हैं। नीचे की दो परतें दो सार्वजनिक दस्तावेज़ों पर आधारित हैं; ऊपर की परत हमारा शोध है। (नीचे के कोड उदाहरण अंग्रेज़ी में हैं।)

  1. SCOS layer · /scos/v1Smart City Operations Support (this research, not in the two documents): dependency links between city services, cascade trace, who acts next, officer decisions.
  2. City Intelligence Layer · /cil/v1City OS and City Intelligence Layer paper (2023): analytics APIs, alerts, reports.
  3. Data Exchange · /catalogue/v1, /auth/v1, /resource/v1BIS draft standard on the data exchange (2019): catalogue, access tokens and consent, data access, audit.

Machine-readable lists:मशीन से पढ़ी जाने वाली सूचियाँ: /api (every routeहर रूट) · /scos/v1/openapi (OpenAPI 3.0, SCOS) · /cil/v1/apis (city intelligence APIsसिटी इंटेलिजेंस API)

Quick startजल्दी शुरुआत

Run your own copy (Node.js 22, no packages to install), with the Kanpur profile so the SCOS layer has its registers:

अपनी कॉपी चलाएँ (Node.js 22, कोई पैकेज इंस्टॉल नहीं), कानपुर प्रोफ़ाइल के साथ ताकि SCOS परत के रजिस्टर हों:

cd cityos-dx
DX_CITY_PROFILE=kanpur npm run seed
DX_CITY_PROFILE=kanpur npm start      # https://localhost:8443

The server uses its own test certificate, so pass -k to curl on your own machine. Then try three public calls (no login):

सर्वर अपना टेस्ट सर्टिफ़िकेट इस्तेमाल करता है, इसलिए अपनी मशीन पर curl में -k दें। फिर तीन सार्वजनिक कॉल आज़माएँ (लॉगिन नहीं):

B=https://localhost:8443
curl -k $B/scos/v1                            # what the layer is, counts, sources
curl -k "$B/scos/v1/explore?service=PWR"      # what power cuts cause, and what causes them
curl -k -X POST $B/scos/v1/trace \
     -H 'content-type: application/json' -d '{"start":"RAIN","steps":3}'

SCOS layer APISCOS परत API research addition

The links are coded from news reports of 52 past Kanpur incidents. Every link is evidence level C1 (news, one coder, not checked by hand). Results are suggestions only; nothing is sent to any department and nothing has been validated.

कड़ियाँ कानपुर की 52 पिछली घटनाओं की ख़बरों से दर्ज की गई हैं। हर कड़ी का साक्ष्य स्तर C1 है (ख़बर, एक व्यक्ति, हाथ से नहीं जाँची गई)। नतीजे सिर्फ़ सुझाव हैं; किसी विभाग को कुछ नहीं भेजा जाता और कुछ भी प्रमाणित नहीं है।

CallWhat it givesLogin
GET /scos/v1About the layer: note, evidence levels, counts, the catalogue items it readsNo
GET /scos/v1/servicesCity services in the register, with owner and number of linksNo
GET /scos/v1/linksThe links; filter with service, direction (up, down, both), department, crossBoundary, minIncidentsNo
GET /scos/v1/explore?service=PWR: upstream, downstream and the incidents behind them. ?department=KESCO: hand-overs to and from that departmentNo
POST /scos/v1/traceFrom start, follow links seen in at least minIncidents (default 2) incidents for up to steps (1 to 6, default 3); returns affected services, links used and "who acts next"No
GET /scos/v1/scenariosThe three demonstration scenarios: S1 rain, S2 power cut to water, S3 road worksNo
POST /scos/v1/decisionsApprove, hold or reject one suggested task (scenario, order, decision, reason); written to the signed audit logICCC operator
GET /scos/v1/decisionsThe decision recordOperator, admin, auditor
GET /scos/v1/openapiOpenAPI 3.0 description of these callsNo

The link register is also an ordinary public data exchange item, so any data exchange client can read it:

कड़ियों का रजिस्टर एक सामान्य सार्वजनिक डेटा एक्सचेंज आइटम भी है, इसलिए कोई भी डेटा एक्सचेंज क्लाइंट इसे पढ़ सकता है:

curl -k "$B/resource/v1/search?id=urn:demo-cat:deplinks/dependency-links-52"

Each row has a fingerprint. If a row is changed quietly, /ops/v1/transparency shows it under dependencyRegister.

हर पंक्ति का एक फ़िंगरप्रिंट है। अगर कोई पंक्ति चुपचाप बदली जाए, तो /ops/v1/transparency उसे dependencyRegister में दिखाता है।

Data exchangeडेटा एक्सचेंज

Find data in the catalogue, then read it. Public items need no token. Protected, private and confidential items need a token from the authorization service, which needs an identity (an officer login or a certificate) and the owner's consent.

कैटलॉग में डेटा खोजें, फिर पढ़ें। सार्वजनिक आइटम के लिए टोकन नहीं चाहिए। संरक्षित, निजी और गोपनीय आइटम के लिए ऑथराइज़ेशन सेवा से टोकन चाहिए, जिसके लिए पहचान (अधिकारी लॉगिन या सर्टिफ़िकेट) और मालिक की सहमति चाहिए।

curl -k "$B/catalogue/v1/search?q=water"                  # find items
curl -k "$B/catalogue/v1/items?id=<item id>"                 # one item, JSON-LD
curl -k "$B/resource/v1/latest?id=<public item id>"          # read a public item
curl -k -X POST $B/auth/v1/token -H 'content-type: application/json' \
     -d '{"request":[{"id":"<item id>"}],"purpose":"..."}'   # token (needs identity)
curl -k "$B/resource/v1/latest?id=<item id>" -H 'Authorization: IUDX <token>'

City intelligenceसिटी इंटेलिजेंस

Each analytic is an API under /cil/v1/{domain}/{api}. List them, read one's OpenAPI description, then call it.

हर एनालिटिक /cil/v1/{domain}/{api} के नीचे एक API है। सूची देखें, किसी एक का OpenAPI विवरण पढ़ें, फिर उसे बुलाएँ।

curl -k $B/cil/v1/apis
curl -k "$B/cil/v1/openapi?path=<path from the list>"
curl -k $B/cil/v1/alerts

Officer login (for decisions)अधिकारी लॉगिन (फ़ैसलों के लिए)

Logging in gives a session cookie and a CSRF token. Calls that change something must send the token in the x-csrf-token header. On a demo copy the logins are listed in docs/HOSTING.md; on any shared copy, use your own account. Most people will use the officer console (screen "SCOS tasks") instead.

लॉगिन करने पर एक सेशन कुकी और एक CSRF टोकन मिलता है। कुछ बदलने वाली कॉल को टोकन x-csrf-token हेडर में भेजना होता है। ज़्यादातर लोग अधिकारी कंसोल (स्क्रीन "SCOS tasks") इस्तेमाल करेंगे।

curl -k -c jar -X POST $B/auth/v1/login -H 'content-type: application/json' \
     -d '{"username":"<operator login>","password":"<password>"}'   # answer has "csrf"
curl -k -b jar -X POST $B/scos/v1/decisions -H 'content-type: application/json' \
     -H 'x-csrf-token: <csrf>' \
     -d '{"scenario":"S2","order":2,"decision":"hold","reason":"Waiting for restoration time"}'

Rulesनियम

  • This is a research prototype. Data is synthetic, except the past incident summaries and the links coded from them, which come from public news reports.
  • Do not present anything from these APIs as official, certified or live city information.
  • Every call that changes something, and every protected read, is written to the signed audit log.
  • Never put a password or token in code you share.
  • यह शोध प्रोटोटाइप है। डेटा सिंथेटिक है, सिवाय पिछली घटनाओं के सारांश और उनसे दर्ज कड़ियों के, जो सार्वजनिक ख़बरों से हैं।
  • इन API से कुछ भी आधिकारिक, प्रमाणित या चालू शहरी जानकारी के रूप में न दिखाएँ।
  • कुछ बदलने वाली हर कॉल, और हर संरक्षित पढ़ाई, हस्ताक्षरित ऑडिट लॉग में लिखी जाती है।
  • पासवर्ड या टोकन कभी साझा कोड में न डालें।
